# 評価ルーブリック

この文書は、`SKILL.md`だけでは判断しにくい場合に参照する。
合計点で機械的に結論を出さず、重大な欠落やガードレール違反を優先する。

## 1. リスク分類

| 水準 | 目安 | 最低限必要な対応 |
|---|---|---|
| LOW | 小範囲、容易に取り消せる、損失が限定的 | 簡潔な比較と次の一手 |
| MEDIUM | 複数利用者、一定の費用・運用負担、復旧可能 | ベースライン、成功条件、主要ガードレール |
| HIGH | 顧客、本番、売上、品質、個人情報、契約に影響 | 人間の決定者、停止条件、ロールバック、限定導入 |
| CRITICAL | 人命、重大法令違反、不可逆な大損失、広範なセキュリティ影響 | AI単独でGOにしない。専門家・責任者による明示承認と独立検証 |

複数水準に該当する場合は高い方を採用する。

## 2. 証拠品質

| 状態 | 定義 | 扱い |
|---|---|---|
| STRONG | 実環境の直接観測、再現可能なテスト、一次資料、複数の整合する証拠 | GO判断の主要根拠にできる |
| MODERATE | 限定データ、類似環境、単一の信頼できる資料、再現性が一部未確認 | PILOTの根拠になり得る |
| WEAK | 伝聞、単一事例、推測、比較不能な過去データ | 仮説として扱う |
| MISSING | 判断に必要だが存在しない、または取得不能 | 結論を変え得るならHOLD要因 |
| CONTRADICTORY | 信頼できる証拠同士が矛盾 | 矛盾を解消する実験または追加確認を優先 |

証拠量が多くても、同じ欠陥を共有するデータだけなら品質は上がらない。

## 3. スコアカード設計

### Primary outcome

一つに絞る。複数ある場合は優先順位を示す。

良い例:
- 課金回復成功率を改善する
- 納期遅延の早期検知を可能にする
- 有料診断の受注可能性を検証する

悪い例:
- 全体的に良くする
- AI化する
- 便利にする

### Guardrails

最低限、次から該当項目を選ぶ。

- 品質・正確性
- セキュリティ・プライバシー
- 法務・契約
- 顧客・利用者負担
- 現場・運用負担
- 障害率・復旧時間
- コスト・利益率
- 保守性・属人化
- ブランド・信用
- 公平性・アクセシビリティ

主指標が改善しても、重大なガードレール違反が一つあればGOにしない。

### Threshold

閾値には根拠を添える。

- 契約、SLA、法令、既存基準
- 現行ベースライン
- 顧客が許容する上限
- 実験で検知できる最小差
- 復旧能力から逆算した上限

根拠がなければ、数値を作らず「全対象で再現しない」「重大事故ゼロ」など観察可能な条件にする。

## 4. 可逆性と観測可能性

### 可逆性

- **HIGH**: 数分〜数時間で戻せ、データ損失がない
- **MEDIUM**: 手順と担当者があり、許容時間内に戻せる
- **LOW**: 移行や顧客影響が残る、復旧に長時間かかる
- **NONE**: 実質的に取り消せない

### 観測可能性

- **HIGH**: 成否とガードレールをリアルタイムまたは判定期限内に検知できる
- **MEDIUM**: 一部は手動確認が必要
- **LOW**: 問題が顧客申告や長期結果まで見えない
- **NONE**: 成否を評価するデータがない

可逆性または観測可能性がLOW以下なら、対象範囲を縮小するかHOLDにする。

## 5. 最小の安全な実験パターン

| パターン | 向く状況 | 注意点 |
|---|---|---|
| Retrospective test | 過去データで正解が確認できる | データ漏洩、時系列リーク、現在との分布差 |
| Shadow mode | 新方式の出力を本番判断に使わず比較できる | 本番負荷、ログの個人情報 |
| Dry run | 削除、送信、更新前に対象と結果を確認できる | 実行時との差を残さない |
| Staging / sandbox | 本番同等環境を再現できる | 外部依存や実データ差 |
| Feature flag | 対象を即時切替できる | フラグ経路自体のテスト |
| Canary rollout | 少数へ段階公開できる | 少数でも重大被害が起き得る場合は不適 |
| Manual review | AI・自動化の判断を人が確認できる | レビュー負荷と形骸化 |
| Time-boxed pilot | 期間と対象を限定できる | 終了後の判定日を固定する |

## 6. 判定ゲート

### GO

すべて満たす。

- Primary outcomeと成功条件が明確
- 主要ガードレールに違反していない
- 残るUnknownsが結論を反転させにくい
- 実行・監視・復旧の責任者が明確
- HIGH以上では停止・ロールバックが実行可能

### PILOT

すべて満たす。

- 有望な根拠がある
- 不確実性を限定実験で減らせる
- 実験中の重大リスクをガードできる
- 成否を観測できる
- 終了条件と判定日がある

### HOLD

一つでも該当すれば候補。

- 結論を変え得る必須証拠がない
- 決定権、契約、環境、復旧手段がない
- 成否または重大リスクを観測できない
- 重要な証拠が矛盾したまま
- 実験設計は可能だが、開始条件を満たしていない

### STOP

一つでも該当すれば候補。

- 重大なガードレール違反が確認された
- 最悪時損失が許容不能で、緩和できない
- 目的に対して現状維持または代替案が明確に優位
- 法令、契約、安全上の禁止に抵触
- 仮説を反証する十分な証拠がある

## 7. 確信度

- **HIGH**: 結論を直接支える強い証拠が複数あり、主要Unknownsが少ない
- **MEDIUM**: 結論は妥当だが、限定データまたは重要な仮定が残る
- **LOW**: 証拠が弱い、矛盾がある、または結論を変え得るUnknownsが多い

確信度は判断の良し悪しではなく、根拠の確かさを表す。
